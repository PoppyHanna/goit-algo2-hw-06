**Task 1**

Фільтр Блума дозволяє ефективно перевіряти унікальність елементів без збереження самих даних, що економить пам'ять. У завданні виконано кілька хеш-функцій для зменшення ймовірності хибно позитивних результатів.
Перевірка паролів відбувається швидко, навіть для великих наборів даних, оскільки операції з бітовим масивом мають низьку складність.
Код враховує некоректні або порожні паролі, що забезпечує стабільність роботи програми.
Основний недолік фільтра Блума - неможливість видалення елементів і наявність невеликої ймовірності помилки, коли новий пароль може бути помилково визначений як уже використаний.


**Task 2**

Точний підрахунок за допомогою структури set забезпечує абсолютно коректний результат, але потребує значних обчислювальних ресурсів — як пам’яті, так і часу, особливо при роботі з великими обсягами логів.
HyperLogLog показав наближений результат із незначною похибкою (звичайно в межах 1–2%), але значно швидше виконав обчислення та спожив набагато менше пам’яті. 
Для аналітики великих даних або потокових логів HyperLogLog є ефективним компромісом між швидкістю, точністю та споживанням ресурсів. Для малих або критично точних вибірок доцільніше застосовувати класичний метод із set, щоб уникнути навіть мінімальної похибки.
Отже, HyperLoglog доцільно використовувати в системах моніторингу, статистики або Big Data-проєктах, де важлива швидкість і масштабованість, а не абсолютна точність.
